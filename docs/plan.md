# Project Plan

## Project Name

Technology & Career Portfolio

## Project Overview

The goal of this project is to develop a professional two-page website that presents my education, technology interests, developing skills, projects, and career goals. The project will use HTML and CSS and will be published through GitHub Pages.

This plan outlines the potential risks, strategies for managing those risks, and the tasks required to complete the project. It follows the planning principles from Chapter 4 of Project Management for the Unofficial Project Manager.

## 1. Risk Analysis

Before beginning development, I identified several risks that could affect the project's completion. Each risk is evaluated based on its impact and probability using a scale of 1 to 5.

Actual Risk = Impact × Probability

Risks scoring 12 or higher will receive a specific risk management strategy using the TAME framework.

### Risk Identification and Prioritization

| Risk | Impact | Probability | Risk Score |
|---|---:|---:|---:|
| Falling behind schedule | 5 | 3 | 15 |
| HTML or CSS errors | 4 | 4 | 16 |
| GitHub Pages publishing issues | 4 | 3 | 12 |
| Missing required documentation | 5 | 2 | 10 |
| Losing project files or changes | 4 | 2 | 8 |
| Website design inconsistencies | 3 | 3 | 9 |
| Adding unnecessary features | 3 | 2 | 6 |

### TAME Risk Management Strategies

TAME stands for Transfer, Accept, Mitigate, and Eliminate. The following strategies will be used to address the identified risks.

| Risk | Score | TAME Strategy | Planned Action | Responsible Person |
|---|---:|---|---|---|
| Falling behind schedule | 15 | Mitigate | Divide the project into smaller tasks and track progress regularly to avoid leaving everything until the deadline. | Tate Neuman |
| HTML or CSS errors | 16 | Mitigate | Test both pages throughout development and correct errors before moving to the next stage. | Tate Neuman |
| GitHub Pages publishing issues | 12 | Mitigate | Publish the website early and verify that both pages and the stylesheet load correctly. | Tate Neuman |
| Missing documentation | 10 | Eliminate | Use a checklist of required files before final submission. | Tate Neuman |
| Losing project files | 8 | Mitigate | Commit changes regularly to GitHub to maintain previous versions. | Tate Neuman |
| Design inconsistencies | 9 | Mitigate | Use one external stylesheet and review both pages for consistency. | Tate Neuman |
| Unnecessary features | 6 | Eliminate | Follow the approved scope statement and avoid adding features outside the project requirements. | Tate Neuman |

Lower-scoring risks will still be reviewed throughout development to ensure they do not become more serious.

## 2. Work Breakdown Structure (WBS)

The project will be divided into smaller deliverables and activities to make the work easier to organize and complete.

### 1. Project Planning

- Review Project 03 requirements.
- Revise the Project Scope Statement using peer feedback.
- Identify and prioritize project risks.
- Create the project plan and task schedule.

### 2. Website Development

- Create `index.html`.
- Add homepage content covering education, technology interests, skills, projects, and career goals.
- Create `about.html`.
- Add information about my background and interests.
- Add navigation links between both pages.

### 3. Website Styling

- Create `style.css`.
- Choose a consistent color palette and fonts.
- Style the header, navigation, main content, and footer.
- Apply consistent styling to both pages.
- Check readability and spacing.

### 4. GitHub Repository

- Create a public GitHub repository.
- Upload the HTML and CSS files.
- Create a professional `README.md`.
- Add links to the live website and documentation folder.
- Create the `docs/` folder.

### 5. Project Documentation

- Add the revised `scope.md`.
- Complete the risk analysis and task schedule in `plan.md`.
- Create `retrospective.md` reflecting on the project process.

### 6. Testing and Final Submission

- Test navigation between both pages.
- Verify that the CSS loads correctly.
- Review website content for spelling and formatting errors.
- Publish the website through GitHub Pages.
- Verify that all required files are present.
- Submit the public GitHub repository link.

## 4. Critical Path

The critical path represents the sequence of activities that must be completed on time to avoid delaying the final project.

The planned critical path is:

Project Planning → Homepage Development → About Page Development → CSS Styling → GitHub Repository Setup → Website Testing and Publishing → Final Review

Delays in these activities could affect the overall completion date. I will prioritize these tasks and regularly check progress.

## 5. Project Resources and Budget

I will be responsible for completing all project activities. My instructor and classmates will provide feedback when appropriate.

The project will use the following free resources:

- HTML and CSS for website development.
- A code editor for creating and editing files.
- GitHub for version control and repository management.
- GitHub Pages for website publishing.
- Course materials and peer feedback for project guidance.

The expected project budget is $0.

## 6. Monitoring and Adjustments

I will review progress after completing each major task and compare it against the project schedule. If a problem occurs, I will identify its impact and adjust the remaining activities while maintaining the approved project scope.

GitHub commits will help track changes and preserve earlier versions of the project. Testing throughout development will also help identify problems before final submission.

## 7. Project Completion

The project will be considered complete when the public GitHub repository contains:

- `index.html`
- `about.html`
- `style.css`
- `README.md`
- `docs/scope.md`
- `docs/plan.md`
- `docs/retrospective.md`

The README will include links to the live website and project documentation. Both website pages must function correctly and share consistent styling.

The final deliverable will be the public GitHub repository link submitted to the instructor.
